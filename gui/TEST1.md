# 测试1：刀具与人脸并行识别

在「切换」选择「测试1」，进入「运行」，点击「开始测试1识别」。程序每约 1.2 秒从逻辑「识别摄像头」取一张新帧，分别异步发送给本机刀具 DINOv3 服务（端口 20005）和 ArcFace 服务（端口 20004）。两路请求各最多一个在途；不会堆积旧帧。结果显示在「运行」「状态」页，人脸框叠加在识别预览上。切换输入源、切换任务或停止识别会丢弃旧结果。

刀具识别默认把摄像头整帧送给服务。服务先在低分辨率图像上自动估计单刀取景框，GUI 显示本次取景尺寸；未找到可靠单刀区域时退回整帧并提示。「手动修正取景」仅供诊断或自动取景失败时使用，「恢复自动取景」清除手动区域。人脸识别始终使用完整画面。

对于单张刀具**打印照片**，先用完整画面。2026-09-29 15:34–15:35 的 7 张刀 2 现场照片整帧识别均以 `knife_02` 为第一候选；按刀具局部裁剪后 6 张变成 `knife_01`、1 张变成 `knife_09`。照片中白色刀刃与白纸接近，局部裁剪的前景分割主要留下深色刀柄；整帧分割则包含整张纸及印刷数字「2」，因此整帧结果也不能当成对真实刀具的可靠验证。遇到 1/2 混淆时可点击「恢复自动取景」复测，并查看界面的次选类别和分差。分差低于 0.05 时界面提示「易混淆」；这个值只用于提示，尚未通过独立测试集校准。

2026-09-29 15:52–15:55 的 9 张打印照片分别是刀 7（4 张）、刀 10（2 张）、刀 3（3 张）。刀 10、刀 3 在局部裁剪后均排对；刀 7 局部裁剪后 4 张均排成刀 9，整帧也在刀 7/8 之间摆动。刀 7 的浅色刀刃与白纸接近，局部裁剪的前景比例仅约 5%–6%；整帧约 67%–72% 是被当作前景的纸张。界面现在对前景比例低于 10% 提示「可能漏掉刀刃」，高于 50% 提示「可能包含背景」。这些比例仅用于输入质量提示，不是已校准的识别阈值。打印图建议换深色背景显示或使用实体刀具、均匀照明再验证。

刀具模型只给出十种刀具的**候选类别与余弦相似度**，没有“无刀具”类别或已验证的在场阈值。界面不会把候选类别称作已检出刀具。当前测试1不发送 STM32 控制命令；软件急停按钮只停止识别，不能制动底盘。

## 板端身份库

- 刀具模板：`/home/orangepi/pi_upper/models/knife/dinov3_448_fp16_v1/templates.json`，由刀具服务启动时读取。
- ArcFace 人脸库：`/home/orangepi/vision_compare_results/face_db.npz`，服务以 `DB_PATH` 指向该文件，请求时自动读取。
- DINOv3 人脸备用模板：`/home/orangepi/vision_compare_results/face_dino_gallery.json`。它与刀具模板分开保存，测试1界面只显示 ArcFace 人脸结果。

建库命令（只读取 `face_enroll/suspect_01…10/reference.jpg`，同时核对 DINOv3 人脸模板来源，用全部十张登记照做冒烟测试）：

```bash
cd /home/orangepi/pi_upper
/home/orangepi/vision_compare_pi_upper/bin/python gui/scripts/build_test1_face_db.py
```

服务以用户级 systemd 单元运行；安装后登录用户会自动加载刀具模型及 ArcFace 模型，测试1开始时直接使用两库：

```bash
cd /home/orangepi/pi_upper
/home/orangepi/vision_compare_pi_upper/bin/python -m pip install -r vision/knife/requirements.txt
mkdir -p ~/.config/systemd/user
cp gui/systemd/test1-{knife,face}.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now test1-knife.service test1-face.service
curl http://127.0.0.1:20005/health
curl http://127.0.0.1:20004/health
```

若摄像头未接入，「运行」页会显示等待识别摄像头。连接 USB 摄像头后重新启动 Qt 上位机以刷新设备枚举。本次板端部署通过 `PYTHON=/home/orangepi/miniconda3/envs/pi_upper/bin/python` 启动 `gui/run.sh`；手动运行时也应指定该解释器。摄像头原始帧仍可用「拍照」保存。

## 2026-09-29 单刀 ROI 补救

已框选单把刀具时，GUI 会通知刀具服务这是单刀 ROI。若常规分割的前景比例低于 20%、首选相似度低于 0.8，服务额外对保留完整 ROI 的四个直角方向推理；只有新分数至少提高 0.07 且前两类分差至少 0.03，才改用新候选。界面出现「已补救浅色刀刃」表示采用了这一路结果。当前默认由服务自动框选；本段记录此前手动 ROI 的验证结果。

改动前的 16 张现场打印照片，在手动单刀框选后为 5/16；改动后为 16/16，最慢约 2.1 秒。早期 5 张实拍保持 5/5。另用从登记图生成的 300 张困难图模拟开启单刀 ROI，结果从 297/300 到 300/300；该合成集不能估计独立现场准确率。打印照片仍不能替代实体刀具测试，且目前没有经过校准的无刀/未知刀拒识阈值。


## 2026-09-29 默认自动取景

服务默认在最长边 640 像素的图像上定位浅色纸面及纸内显著区域，根据目标长宽比调整取景框，再送入原刀具模型。无浅色纸面时尝试简单前景框；自动取景失败时退回整帧。响应包含 `roi_xyxy` 和 `roi_source`，界面显示自动取景状态。调用方已自行裁剪时传 `roi_selected=true` 跳过二次取景。

以服务默认参数上传 16 张板上原始相机帧（刀 2/7/10/3 的打印照片），均返回自动框，类别为 16/16；另有 Qt GUI 整帧请求验证通过。这些照片不能代表实体刀具、多刀同框或复杂背景；模型仍只给候选，未校准无刀拒识。
