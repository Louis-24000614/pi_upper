# 手动棋盘格地面标定网页

独立入口 `gui/manual_calibration_web.py`，默认端口 8082。现有 AprilTag 网页和 GUI 标定功能保持原样。
支持冻结/上传、计算、预览、独立保存、点击测距检查及明确选择应用/恢复。保存不自动应用。
不覆盖 `nav_camera.yaml`、`culvert.yaml`，不修改运动参数、停车保护或 UART；应用记录单独保存，导航下次启动时读取。

## 启动

使用项目已有 Python、OpenCV、NumPy、PyYAML，无需额外网页框架。
开发与离线使用下列命令，不打开相机、串口，也不启动导航：

```sh
python -u -B gui/manual_calibration_web.py --offline --bind 127.0.0.1 --port 8082
```

打开 `http://127.0.0.1:8082/`，上传原始 PNG/JPEG。也可以预载图片：

```sh
python -u -B gui/manual_calibration_web.py --offline --image /absolute/path/raw.png --port 8082
```

局域网离线上传可用 `--bind 0.0.0.0`（默认）。`--output` 可指定离线验证的临时结果目录；正式默认目录为 `data/calibration/manual/`。
临时 `--output` 目录禁用应用/恢复，避免测试数据影响项目导航。已有原图在默认目录离线标定也可应用，但须明确确认来源和误差。

以下现场命令会打开导航相机，须在取得相机操作授权后运行，并先结束占用该相机的程序：

```sh
cd /home/orangepi/pi_upper
python3 -u -B gui/manual_calibration_web.py --port 8082
```

同一局域网打开 `http://<板端IP>:8082/`。设备、宽、高只读自 `--config` 指定的导航配置，默认 `config/nav_camera.yaml`；
板端当前为 `/dev/nav_camera`、1280×720。没有另外的设备/分辨率默认值，实际采集尺寸不符时拒绝冻结。
本机旧工作副本可能仍配置 `/dev/video0`，以启动机器上的导航配置为准。
页面“停止网页并释放相机”或终端 Ctrl+C 可退出；不会自动结束其他占用相机的进程。

## 选点与尺寸

1. 把较大的棋盘板平放在道路地面。只让所选矩形区域的四个外角入镜即可，整板无需入镜。
2. 输入横向 N 格、纵向 M 格，均为正整数。这里是区域内**格子数量**，不是内角点数量。
3. 选择一种实际尺寸方式：单格边长（区域宽=N×边长、高=M×边长），或分别实测区域总宽、总高。
   单位 mm/cm，内部换算为米。3×2 格、单格30 mm，对应90×60 mm；页面显示最终采用的宽高。
4. 实时画面先“冻结画面”；上传图自动冻结。按区域自身“1左上、2右上、3右下、4左下”选四个外角，
   得到透视四边形。四点完整后自动计算，也可点击计算按钮。拖动编号点修正，撤销、重新选点、放大和平移均可用。
5. 默认原点为区域中心，X 向区域右侧、Y 向区域上侧。角点不按屏幕位置自动重排。
   凸性和绕向可以检查，区域自身左上起点及实际方向仍须用户核对；旋转的棋盘区域也保留用户选择的编号方向。

选点数据始终保存为原图像素。画布使用独立的显示变换，点击先扣除画布留白、平移，再除以显示比例；
考虑页面缩放的实际显示边界和高 DPI。缩放与平移不修改已有点，图片不经过尺寸缩放后再保存。
图片解码不应用 EXIF 旋转，不进行镜头去畸变；图像空间记录为 `raw_distorted`。
不同分辨率的上传图可独立标定，页面会提示导航原 H 与该图不能直接比较，不猜测缩放内参。

## H 与坐标基准

页面展示服务启动时只读的导航参数估算 H（图像→车辆地面米、图像→导航BEV像素）及来源分辨率；
只读导航相机高度、俯角和内参作为备用参数估算。同时展示已选手动标定及导航下次启动采用的车辆 H；
网页不能断言另一个已运行的导航进程是否已重启，因此不把“已选择”显示成“当前实车已切换”。
标定后的 H 由四个像素外角与下列区域米坐标求得：

```text
左上 (-宽/2, +高/2)    右上 (+宽/2, +高/2)
左下 (-宽/2, -高/2)    右下 (+宽/2, -高/2)
```

`H_img_to_region_ground_m` 输出区域坐标；`H_img_to_preview_px` 只用于等比例俯视预览。
H 将 `[u,v,1]` 映射为齐次坐标，再除以第三分量，不能将 BEV 像素矩阵直接当成米制矩阵。

可选填写区域中心相对导航相机光心地面垂足的 X/Y 距离。只有勾选“区域X向车右、Y向车前”且两项距离完整时，
才平移区域地面坐标并另存车辆坐标候选 `H_img_to_vehicle_ground_m`。未确认时仅保存区域坐标；
区域中心不会被直接当成相机原点。候选保持 `verified=false`、`applied=false`，不自动应用。

四点拟合成功**不代表整个测距范围精度已验证**。后续须用没有参与拟合的独立距离点检查尺度、方向和镜头畸变影响。
原始带畸变图像的单应模型不能消除镜头径向畸变。本轮不调整运动参数或停车保护。

## 独立保存与失效处理

每次结果保存到 `data/calibration/manual/<UTC时间_随机ID>/`：

- `raw.png`：原始冻结/上传像素，无角点标注。
- `corners.png`：四个编号外角与四边连线。
- `bev.png`：区域坐标等比例俯视预览，标明 X/Y。
- `calibration.json`：相机来源、实际原图尺寸、N/M、尺寸方式和单位、米制宽高、角点顺序、像素/地面坐标、原点和轴、
  当前导航原 H、区域新 H、预览 H、冻结/计算/保存时间、带畸变及未验收/未应用状态。
- `vehicle_candidate.json`：仅经用户确认方向并填写距离时生成，车辆地面原点、测量偏移、候选四点及 H 单独保存。

重新冻结/上传清除旧点和结果，输入或拖点立即清除旧 H 与保存资格。
服务器按冻结ID、输入版本和结果ID拒绝旧请求，并在保存时复核输入、角点和矩阵。
当前结果重复点击保存返回同一个文件，不覆盖既有结果；新计算结果保存到新的唯一目录。
文件先写到本次临时目录，全部成功后发布，写入失败不会留下声称成功的 JSON。

## 测距检查、应用与恢复

点击“点击图像检查测距”后，页面用同一原图像素点展示旧参数估算 H 与本次车辆候选 H 的 X/Y，
统一以相机光心地面垂足为原点、以 cm 显示。区域 H 和 BEV 像素 H 不参与对比。
填写实测值并记录后，同时显示两份 H 的有符号误差（计算减实测）及平面总误差。
每个已记录检查点也保留对比表；手机可在表格内横向滑动。旧 H 缺失、原图分辨率不同或旧投影在此点退化时，
显示不可比较的中文原因，仍可核对新 H。修改实测输入会清除当前预览误差，点击新点会清空实测输入；
修改标定参数、重新计算或换图会清除旧检查与对比。对比仅展示，沿用现有检查记录与应用规则。

1. 将棋盘区域 X/Y 与车右/车前对齐，填写区域中心到相机光心地面垂足的实测 X/Y，生成车辆坐标候选。
   例如中心位于相机垂足正前方 40 cm，横向填 0、前向填 40，单位 cm；不要将高度 13 cm 填作前向偏移。
2. 四角计算后点击“点击图像检查测距”，在原图点选其他地面位置。显示区域与车辆坐标，不移动拟合角点。
   输入该点相对相机垂足的实测 X/Y，点击“记录实测值并显示误差”，显示计算值、X/Y 误差及总误差。
   四个拟合角点不可作为检查点。同一个像素点重新记录会替换旧测量；改变角点、尺寸、偏移或图片清除检查记录。
   建议检查涵洞观察范围内多个远近、左右位置；页面不设置未经现场确认的误差容限。
3. 至少记录一个实测检查点，明确确认已核对误差及图像来自当前导航相机，再点击“保存并应用此标定”。
   只允许车辆坐标、当前有效结果、导航原图分辨率。旧冻结、旧输入、不同分辨率、导航配置已改变的结果不能应用。
4. 涵洞另有现有地面接触保护：须人工确认 YOLO 框底边确实对应入口地面，再勾选对应确认。
   未勾选可选择用于循迹，但涵洞自动停车拒绝启动；`--culvert-estimated-camera` 不覆盖已选手动结果或绕过该确认。
5. 应用创建 `data/calibration/manual/active.json`，记录源文件及 SHA256、车辆矩阵、实测检查点、用户确认和应用时间。
   候选源文件仍保持 `verified=false/applied=false`，不回写原始独立标定记录；应用事实和用户核对在单独记录中。
   原选择备份到 `activation_history/`。点击“恢复上次标定设置”可逐次退回，首次应用后恢复即回到原配置。
6. 应用/恢复后须重新启动导航；运行中的进程固定使用启动快照，循迹与涵洞使用同一个车辆坐标矩阵。
   无已选标定时保持原来的参数投影和涵洞配置行为。已选文件损坏、丢失或设备/尺寸不符时拒绝启动，不悄悄退回估算。
   页面支持恢复损坏的当前选择，保留损坏记录备份；若上一份结果也损坏，会报告错误。

导航在打开模型、相机或串口之前核对已选结果，并打印标定源文件；涵洞事件记录也记录来源和检查点。
代码入口为 `vision/ipm_proto/manual_ground.py`、`road_follow.pipeline.make_ipm`、
`road_follow.culvert_runtime.validate_culvert_config`。网页应用不会启动导航、串口或运动。
当前 `culvert.yaml` 还有 `entry_distance_bias_m: -0.10` 距离补偿，保持原值；检查点误差只检验投影，
不能当作整个停车链路已经验收。实际停车位置还需在另行授权的现场验证中核对。

## 离线验证

```sh
python -B -m unittest discover -s gui/tests -p 'test_manual_calibration*.py' -v
node gui/tests/manual_calibration_browser.mjs
```

Python 测试只使用合成大棋盘的局部3×2区域、纯逻辑、本机HTTP和系统临时目录。
覆盖四点/独立内部点映射、非正方形区域、mm/cm、无效四边形与输入、坐标候选、失效请求和保存失败；
另覆盖检查误差、HTTP 应用/恢复、导航与涵洞实际投影入口一致、进程快照、恢复链、原配置不变、
损坏文件/设备/尺寸拒绝、地面接触保护和原子发布失败。
Node 无参数运行显示变换的独立检查。实际浏览器检查可在离线服务启动后使用已有 Playwright 和 Edge：

```text
node gui/tests/manual_calibration_browser.mjs <离线网页URL> <合成原图路径> <临时截图目录> <已有playwright/index.mjs路径>
```

浏览器脚本默认 `msedge`，可通过 `MANUAL_BROWSER_CHANNEL` 指定已有 Chromium 通道，不自动安装依赖或浏览器。
覆盖桌面（含160%画布放大后拖点）、75%页面显示缩放+50%画布缩放+平移，以及高DPI手机视口触摸；验证原图像素、拖点、上传重置与保存流程。
实际导航相机、镜头畸变、棋盘贴地程度、现场鼠标/手机设备和测距精度仍需另行实测。
