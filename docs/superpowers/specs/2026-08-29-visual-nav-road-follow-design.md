## 背景与约束

赛题要点（摘自 2026 规则）：

- 场地约 3200×4400 mm，侦察车道两侧有 50 mm 高挡板，路宽约 800 mm。
- 考核纯视觉端到端神经网络做道路分割等感知；不使用超声/激光/主动红外可获加分。
- 未建图导航；途中遇障碍需重规划（本阶段不做障碍逻辑，但流水线需能扩展）。
- 上位机跑在 Orange Pi 5 Plus（RK3588，NPU ≥6 TOPS），与 STM32 下位机经 UART 协议 v2 通信，50 Hz `CMD_VEL`。

仓库既有架构（`docs/architecture/overview.md`）已约定：`vision`（YOLO-seg / RKNN）→ `navigation`（BEV · 栅格 · 规划）→ `state` → `uart`。本规格是该链路的 Stage-1 落地定义。

## 目标与非目标

**目标**

1. 训练并部署 **YOLOv11 Nano 分割模型（YOLOv11n-seg）**，单类 `road`。
2. 将道路 mask 经轻量 IPM/BEV 转为车体附近可行驶区域，提取中心线。
3. 用 Pure Pursuit（或等价横向控制器）输出期望线速度/角速度，经状态机下发到下位机。
4. 直道居中、缓弯跟线，mask 丢失时安全减速/停车。

**非目标（明确不做）**

- 障碍物类别、避障与路径重规划
- 涵洞侦察、嫌疑人/物体识别、人脸
- 隧道暗光专项策略
- 12 个巡查点的拓扑全局规划与 UID 播报
- 在线 SLAM / 全局建图

## 总体架构

```text
前视全局快门相机
        │
        ▼
  vision (RKNN)
  YOLOv11n-seg → road mask (+ 时间戳)
        │
        ▼
  navigation
  IPM/BEV → 中心线 → Pure Pursuit → (v, ω)
        │
        ▼
  state（自主寻线 / 停车 / 手动遥控；手动优先）
        │
        ▼
  uart  50 Hz CMD_VEL
```

分工一句话：**YOLO-seg 只回答「哪是路」；「怎么开」在 BEV + 跟踪层。**

## 感知：YOLOv11n-seg

| 项 | 约定 |
| --- | --- |
| 模型 | YOLOv11n-seg（Nano） |
| 类别 | 单类 `road` |
| 输入边长 | 优先 640；若板端延迟不足再试 512 |
| 训练数据 | 前视导航相机实采；多边形标注道路；覆盖直道/弯道、偏航、远近、常见光照 |
| 训练主机 | 现有规划中的 4070Ti 主机 |
| 部署路径 | 训练 → ONNX → RKNN-Toolkit2 量化 → `.rknn`，文件放 `models/`（不提交仓库） |
| 板端帧率 | 导航环稳定使用最新推理结果即可，目标推理 ≥10–15 Hz |
| 输出 | 二值 road mask（置信度阈值可配），供 `navigation` 消费；调试时可叠加到画面 |

标注约定：道路表面为前景；50 mm 侧挡板、赛场外区域、非道路地面不标为 `road`。交叉口处所有可见可行驶路面标为 `road`，方向选择留给后续拓扑层。

## BEV、中心线与跟踪

**IPM / BEV**

- 使用相机固定外参（安装高度、俯仰、偏航）做透视变换；Stage-1 不在线估计姿态。
- BEV 关注车前约 0.3–1.5 m、横向约覆盖 0.8–1.0 m（匹配约 800 mm 路宽）。
- 标定结果以配置文件形式保存，便于现场微调。

**中心线**

- 在 BEV 的 road mask 上按行（或沿纵向栅格）取可行驶区间中点，得到离散中心点列。
- 近端点权重高于远端；可做轻度平滑，抑制 mask 锯齿。
- 若某行无道路像素，该行不参与拟合。

**跟踪控制**

- 默认 Pure Pursuit：在中心线上取 lookahead 点，由几何关系求角速度；线速度先常值或按曲率分段降速。
- 输出为车体坐标系下期望 `(v, ω)`，单位与 UART `CMD_VEL` 一致。
- 交叉口 Stage-1 策略：沿当前视野内道路自然延伸前进，不做强制左右分支选择。

## 模块边界与接口

逻辑模块与既有架构对齐；物理目录随实现时确定。

| 模块 | Stage-1 职责 |
| --- | --- |
| `camera` | 前视 UVC 采集，发布带时间戳帧 |
| `vision` | 加载 YOLOv11n-seg.rknn，输出 road mask |
| `navigation` | mask → IPM → 中心线 → Pure Pursuit → `(v, ω)` |
| `state` | 三态：自主寻线 / 停车 / 手动遥控；手动指令覆盖自主 |
| `uart` | 50 Hz 采样最新 `(v, ω)` 下发；与导航线程解耦 |
| `ui` | 显示原图、mask 叠加、BEV/中心线、当前 `(v, ω)`（调试用） |

进程内传递：图像与 mask 用带时间戳的共享缓冲（读最新）；导航不阻塞采集；控制环不因偶发推理变慢而停发串口（用上一拍有效指令或零速策略，见下节）。

## 失效与安全

| 条件 | 行为 |
| --- | --- |
| mask 置信度低 / 道路像素过少 | 减速直至停车，角速度置 0 |
| 中心线无法拟合（弯太大、出界） | 停车，等待恢复或切手动 |
| 推理超时或 vision 线程异常 | `state` 视为感知失效 → 停车；`uart` 仍按 50 Hz 发零速或保持协议要求的心跳 |
| 操作者切手动 | 立即以遥控 `(v, ω)` 为准 |

不在 mask 丢失时盲目沿上一帧中心线冲刺。

## 验收标准

先录包/台架，再实车低速：

1. **直道**：能大致居中行驶，不持续蹭两侧 50 mm 挡板。
2. **缓弯**：能跟线转弯，不冲出道路表面。
3. **失效**：遮挡镜头或驶偏导致 mask 丢失时，能减速/停车，不出现持续乱转。
4. **时延**：相机曝光完成到 `(v, ω)` 更新的端到端延迟目标 &lt; 100 ms（允许按实车再调）。
5. **链路**：自主寻线模式下，下位机可持续收到 50 Hz `CMD_VEL`，断流看门狗不误触发。

## 后续阶段预留

本阶段接口预留扩展点，避免推倒重来：

1. **多类分割**：在 `road` 上增加 `obstacle`、`curb` 等，不改变 BEV 入口形状（仍是语义 mask / 实例列表）。
2. **栅格占用**：BEV 中心线可升级为占用栅格 + 局部规划（DWA / 混合 A* 等），Pure Pursuit 变为规划轨迹跟踪。
3. **拓扑巡航**：在寻线之上叠加路口决策与任务点序列；寻线层仍负责「贴路行驶」。

## 待确认项

- 前视相机最终分辨率与帧率（建议导航用 1280×720 或更低以保 NPU/带宽）。
- IPM 外参的实测标定流程与配置文件字段名。
- YOLOv11n-seg 在 RKNN 上的实际延迟与是否需要 INT8 量化校准集。
- Pure Pursuit 的 lookahead、限速等初值（实车标定）。
- 训练数据由谁采集/标注、赛场适应日是否允许补采微调。
