# 路口航向参考校正

第一轮只校正下位机离散动作的航向参考，不重估 gyro bias，不清原始 IMU yaw、
编码器或 ODOM。视觉已经摆正后，后续 90° 转向与有限直行动作从该点的 raw yaw
建立方向档位；两次校正之间的 IMU 漂移速率仍由原有估算器决定。

## 触发与导航交接

普通路口与巡检点共用 `HeadingAnchorGate`。交接区内必须有新鲜相机帧、
有效道路方向和新鲜 ODOM；道路角度连续进入原有 0.05 rad 范围。格网边仍要求
8 帧，短边仍要求 5 帧，即使初始角度已在范围内，也必须收集不同帧的稳定证据。
重复帧不增加计数，缺少方向或超时不会放行。

稳定后先向桥写 `0 0`，再写 `anchor_heading`。桥保持零速，下位机通过实际反馈
确认双轮目标为零、双轮实测速度均低于 0.01 m/s 且持续 500 ms。桥收到
`ANCHOR_DONE` 后，导航还要收到更新的 ODOM，才锁定 Pi 航向并执行原来的
17/20 cm 直行。桥丢弃 ACK 前缓存 ODOM 的输出机会，避免旧样本被赋予新接收时间。

等待期间视觉证据丢失、超时、提交失败或下位机拒绝均进入故障停车；
不会把超时当成已经校正。校正不改变原有速度、距离、转向增益和边长保护。

## 两端接口

- UART `0x15 HEADING_REFERENCE`：空 payload。
- HELLO_INFO capability bit4：支持该请求。
- `ACK_OK`：参考已在下位机应用锁内更新，角 PID 已复位。
- `BUSY`：尚未停稳或有活动动作；桥保持零速，每 100 ms 重试，窗口 2 秒。
- ACK 超时：不重发该请求，避免迟到 ACK 冒充另一请求的成功。
- 桥 stdout：`ANCHOR_DONE` 或 `ANCHOR_FAIL <reason>`。

IMU 必须有效且已校准，yaw/Z 轴角速度有限；IMU 和控制反馈均不超过 50 ms。
故障、急停、电机测试或待处理故障时拒绝。ACK 队列满时不能先更新参考。
原有动作结果队列保持完整。完整线协议以 RC 的 `UART_PROTOCOL.md` 为准。

## 配置与兼容

`config/nav_camera.yaml` 新增 `heading_anchor.enabled: true`。拓扑导航启用时给
`uart_vel` 传 `--require-heading-anchor`，旧固件缺少 bit4 时桥在 ARM 前退出。
若明确设置 false，启动日志提示未启用中途参考校正，继续使用原有交接流程；
摆正测量缺失或超时仍不能作为稳定成功。

两端源码必须配套构建。本次已在板端临时目录完成 Linux 构建、UART 伪终端测试
和实际 uart_vel 的假下位机联调。尚未完成 STM32 完整固件链接/烧录和实车校验；
伪终端内的模拟 ACK 不代表真实下位机已经烧录新固件。
