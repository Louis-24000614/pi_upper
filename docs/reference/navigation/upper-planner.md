# 上层路径规划

2026 侦查机器人上位机的任务层约定。它只回答四件事：下一跳去哪个节点、这条边被堵住后换哪条、到了节点往哪边转、哪些点已经算过分。贴线、路口最后几十厘米、读卡和播报的执行不在这里展开。

规则原文是仓库根目录的 `1789106353320933 (1).pdf`。拓扑数据在 [`config/nav_topology.yaml`](../../../config/nav_topology.yaml)。

## 赛题要求

一场比赛从出发区出发，自主选方向，完成下面的事再回到出发区。

| 任务 | 规则 | 规划层怎么对待 |
| --- | --- | --- |
| 12 个巡逻点 | 图 6 的 ①–⑫ 必到；点下有 UID；正确播报「到达 X 号巡逻点」+10 / 处，错误 −10 / 处；每点只计一次 | 12 个固定物理位置都要到；播报号用读到的卡号 |
| 4 段隧道 | 图 6 阴影；洞内无灯；通过 +10 / 段，每段一次 | 这四条边必须被默认路线经过 |
| 8 个涵洞 | 从 20 个蓝色模块加 2 个橙色模块里现场放 8 个；图 6 绿点只是示例 | 路过就识别，不专门绕路去找 |
| 3 个障碍 | 从 20 个蓝色模块里现场放 3 个，距涵洞 10–20 cm | 堵住的边封掉，换路，不从障碍旁边挤 |
| 返回出发区 | +10 | 必到点都处理完之后的最后目标 |
| 驶离出发区 | +5 | 离开 `0_0` 即记一次 |

现场还会抽签决定出场顺序。巡逻点上的卡号、涵洞和障碍的位置由志愿者按出场顺序摆，开赛前不知道。适应时间 5 分钟。三次机会，每次最多 10 分钟，三次合计 20 分钟，取得分最高的一次。

2026 相对 2025 增加了遇障自行重规划，并取消了地面黑色圆标。传感器允许 1–2 个摄像头、1 个陀螺仪、1 个读卡器。超声、激光、主动红外不用，这样才保留纯视觉翻倍。

## 分数怎样约束路线

不计涵洞时：

| 组成 | 分数 |
| --- | --- |
| 驶离出发区 | +5 |
| 12 个巡逻点 | +120 |
| 返回出发区 | +10 |
| 小计 | 135 |

135 不到 150。再通过 2 段隧道（+20）或正确播报 1 个涵洞（+30），才超过 150。超过之后，全程不撞四周 +150，并且纯视觉把总分翻倍。

撞障碍一次 −50。175 分撞一次变成 125，+150 和翻倍一起失去。200 mm 的车道里也没有从障碍侧面绕过去的空隙。

所以顺序是：

1. 看见障碍就封边绕行，不顶、不挤。
2. 12 个巡逻位置和返回出发区都要完成。
3. 四段隧道能过就过；被封的那一段放弃，不反复试。
4. 涵洞是路过得分。为了涵洞钻进已封的边，不做。

## 拓扑

节点名是 `行_列`。行从上往下增大，列从左往右。出发区只有左右两条出口：左边 `1_2` 是图 6 的 ①，右边 `1_3` 是 ⑫。这一排没有 `1_1` 和 `1_4`。括号里的两位数字写在对应节点上，中间十字没有括号。坐标只供画图，搜路用边的连通和 `length_m`。

```text
                 0_0
                /   \
           1_2(01)   1_3(12)
              |         |
2_1(02)----2_2--------2_3--------2_4(11)
 |          |          |          |
3_1(03)----3_2--------3_3--------3_4(10)
 |          |          |          |
4_1(04)----4_2--------4_3--------4_4(09)
 |          |          |          |
5_1(05)----5_2(06)----5_3(07)----5_4(08)
```

| 角色 | 节点 | 到了之后 |
| --- | --- | --- |
| 出发区 | `0_0` | 任务结束停在这里 |
| 巡逻位置 `patrol_slot` | `1_2` `2_1` `3_1` `4_1` `5_1` `5_2` `5_3` `5_4` `4_4` `3_4` `2_4` `1_3` | 读卡、播报、再按路径转向 |
| 普通路口 `junction` | `2_2` `2_3` `3_2` `3_3` `4_2` `4_3` | 没有卡；视觉发现路口后定距补盲，再按路径转向 |

图 6 的 ①–⑫ 只用来对照上表。运行时不把「读到 7」理解成「车在图上的 ⑦」。

```text
slot_id      固定物理位置，例如 2_1
card_number  读卡器读到的 1..12
```

第一次在某个 `slot_id` 读到新卡号时写下映射并播报「到达 X 号巡逻点」，X 是卡号。同一卡号再出现不播报、不转向。映射冲突则停车，不覆盖旧映射。

边全部双向，`length_m` 为正。倒车不写成负边。`blocked` 只在运行时加上，不写进 YAML。

四段隧道在 YAML 里的初标是：

- `2_3__2_4`
- `3_3__3_4`
- `4_3__4_4`
- `4_4__5_4`

进场后若阴影不在这四条边上，只改这四个 `tunnel` 标志，再重算默认路线。节点命名不变。

## 本层与下层

```text
上层 Mission
  剩余巡逻点、剩余隧道、已封的边
  → 下一条边，以及到点后 LEFT / RIGHT / STRAIGHT
  → 下一条就是来路时，倒车，不转 180°
下层执行
  直道：道路掩码 → 中心线 → CMD_VEL
  巡逻点：新读卡事件 → 停车 → 按上面的方向转
  普通路口：远处锁存支路 → 走廊末端定距前进 → 按上面的方向转
  隧道边：冻结视觉航向，靠陀螺把这段开完
```

方向只来自入边和出边。卡号和道路掩码都不决定左转还是右转。对称路口的画面也不能用来猜测自己在全场的哪一个十字；位置来自「从 `0_0` 出发之后实际走过的节点」。

下一条边就是刚走过来的那条时，直接倒车回上一个节点，不原地转 180°。倒车用负的 `CMD_VEL`，车头方向不变。倒回到路口之后，再按下一条出边做 90° 或直行。

手动和急停高于本层。急停之后本层冻结，不把没走完的边记成已完成。

## 无障碍时的默认路线

默认从左侧出口进场，走完 12 个巡逻位置，并经过上面四条隧道，最后从右侧出口回到出发区。走到 `5_4` 和 `2_4` 这两个端点后，沿来路倒车离开，不转 180°。

```text
0_0 → 1_2 → 2_2 → 2_1 → 3_1 → 4_1 → 5_1 → 5_2 → 5_3
    → 4_3 → 4_4 → 5_4 → 4_4 → 3_4 → 3_3 → 2_3 → 2_4
    → 2_3 → 1_3 → 0_0
```

途中对应关系：

| 节点 | 作用 |
| --- | --- |
| `1_2` | 左出口，巡逻点 ① |
| `2_1` `3_1` `4_1` `5_1` `5_2` `5_3` | 左侧和底边巡逻点 ②–⑦ |
| `4_3 → 4_4` | 隧道 `4_3__4_4`，到达 ⑨ |
| `4_4 → 5_4` | 隧道 `4_4__5_4`，到达 ⑧ |
| `5_4 → 4_4` | 在 ⑧ 倒车回到 ⑨ |
| `3_4` `2_4` | 右侧巡逻点 ⑩⑪ |
| `3_4 → 3_3` | 隧道 `3_3__3_4` |
| `2_3 → 2_4 → 2_3` | 隧道 `2_3__2_4`，在 ⑪ 倒车回到中间列 |
| `1_3 → 0_0` | 右出口 ⑫，回到出发区 |

车头朝场地内。这条序列是无障碍时的结果，不是写死的播报顺序。隧道标志改过之后，用同一条规则重搜：未访问的巡逻点、未走过的隧道边、最后回 `0_0`，每步都走当前图上的最短路，拼成一条覆盖路径。

## 遇障重规划

障碍检测连续判定当前走廊过不去时，本层把 `current_edge` 标成 `blocked`，从车所在的 `from_node` 重搜。Dijkstra 已在 `navigation/topo_proto/`。

重搜的目标仍是：还没到的巡逻点、还没走过的隧道边、然后 `0_0`。某个点已经不可达就跳过并记下来，不用车去顶那条边。

车若还在边中间，先沿这条边退回 `from_node`，再沿新路线正向开。倒车距离用沿边进度 `s` 和 `ODOM_STATE`，帽和贴脸短退沿用现有倒车约定。前视相机倒车时看不见身后，不能靠视觉倒到上一个路口。

封边在这一轮比赛里保留。下一次 10 分钟机会重新开始，不继承上一轮的封边和卡号映射。

软绕障不作为本层策略。净宽 200 mm，障碍就等于这条边不能走。

## 到点与转向

入边和出边的夹角决定动作：

| 夹角 | 动作 |
| --- | --- |
| 0° | `STRAIGHT`，继续 `CMD_VEL` 贴线，不发转向 |
| 90° | `LEFT` 或 `RIGHT`，一次 `MOTION_ACTION` |
| 来路 | 倒车回上一个节点，不发 180° |

触发分两类，方向都用上表，不分开计算：

- 下一个节点是 `patrol_slot`：新的读卡 `generation` 才算到达。先停稳，记卡号，播报，再转。没读到卡就低速短搜，超过上限停车，不伪造到达。
- 下一个节点是 `junction`：视觉锁存规划方向上的支路，走廊末端交给编码器定距前进，再转。

转完并且视觉重新咬住新走廊之后，才把 `current_edge` 换成出边、把 `s` 清零。转向失败时，节点停留在转之前的位置。

直道中途即使掩码分叉，只要规划结果是 `STRAIGHT`，就保持当前边，不提前转弯。

## 隧道、涵洞与记忆

隧道边上不更新视觉航向，也不用路口逻辑找支路。进去前记住偏移，出来重新看见路面再拉回。通过整条 `tunnel` 边记一次，重复经过不加分。

涵洞识别在行驶中并行发生。播报过的目标记下来，同一目标不播第二次。识别错了会扣 30 分，没有把握就不播。涵洞位置不写进拓扑，也不因为附近 10–20 cm 可能有障碍就提前封边；等真的看见障碍再封。

这一轮要记住的只有这些：

| 记忆 | 用途 |
| --- | --- |
| `visited_slots` | 哪些物理位置已经到过 |
| `slot_to_card` / `card_to_slot` | 位置和现场卡号的对应 |
| `visited_cards` | 每个卡号只播报、只计分一次 |
| `traversed_tunnels` | 每段隧道只计一次 |
| `blocked_edges` | 这一轮已经确认过不去的边 |
| 已播报的涵洞目标 | 不重复播报 |

这些就是规则里的长时记忆。不建全场稠密地图，也不用里程计坐标去对 YAML 里的 `x/y`。

## 状态

```text
IDLE
  → RUN            裁判开始；车在 0_0，车头朝场内
RUN
  → FOLLOW         沿当前边贴线
  → TUNNEL         当前边带 tunnel
  → ARRIVE_SLOT    读卡到达巡逻点
  → ARRIVE_JUNCTION 视觉路口到达普通路口
  → TURN           按入边/出边转向
  → BLOCKED        封边、退回 from_node、重搜
  → RETURN         必到项完成，目标改为 0_0
  → DONE           回到出发区，停车
  → FAULT          转向失败、卡号冲突、或剩余目标都不可达
```

`FAULT` 停车，不自动改路线撞出去。三次机会之间由人重新摆回出发区，软件从 `IDLE` 另开一轮。

时间接近这一次的 10 分钟、而 12 个点已经到齐时，放弃还没走的隧道，直接 `RETURN`。点还没到齐时，优先剩余的巡逻点，其次才是隧道。
